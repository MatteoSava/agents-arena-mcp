# v0.3 isolation spike (2026-10-27)

This was the go/no-go for the v0.3 experiment bench. It asked, for each harness: can a contestant be isolated so it sees only its own config, does auth survive that isolation, and can exact metrics be read?

Versions tested: claude 2.1.291, codex-cli 0.164.0 (upgraded from 0.133.0, which could not decode the server's model list), opencode 2.1.4. Isolation was checked with a marker instruction (the secret word "PAPAYA") placed in a throwaway home, and by listing the skills and MCP servers the agent actually loaded. The real user config was never modified.

## Verdict: GO, with two constraints

1. **`real` baseline means the user's actual home, untouched, never a copy.** A copied config dir loses auth for claude (keychain) and for opencode (`opencode.db`). In `real` mode, only `repo:` overlays are allowed. `home:` overlays require `clean`.
2. **`clean` baseline means a fresh `HOME`, not just the harness config variable.** Redirecting `CODEX_HOME` alone still leaked about 30 user skills from `~/.agents/skills`. Redirecting `HOME` fixed it. Tool caches must stay on the real paths (for example `UV_CACHE_DIR`, `XDG_CACHE_HOME`), or every run re-downloads dependencies.

## Per harness

| | claude | codex | opencode |
|---|---|---|---|
| Isolation vars | `HOME`, `CLAUDE_CONFIG_DIR` | `HOME`, `CODEX_HOME` | `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`; **must** pass `--standalone` |
| Clean: user skills/plugins/MCP gone? | yes (init event: only built-ins) | yes, once `HOME` is redirected (only 4 system skills) | yes (marker-only config) |
| Clean auth | **no**: macOS keychain is tied to the default dir. Needs `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`) or `ANTHROPIC_API_KEY` in the env | **yes**: copy `auth.json` into the clean `CODEX_HOME` | **partial**: stored logins live in `opencode.db` (112 MB, includes history). Only env-provided keys work, e.g. `OPENROUTER_API_KEY` |
| Real auth | yes (no redirect) | yes | yes |
| Metrics source | final `result` JSON: `usage`, `total_cost_usd`, `num_turns`, `duration_ms` | `turn.completed.usage` (tokens; **no cost**) | not in the `run --format json` stream. Read from `opencode session export <sessionID> --standalone` → `info.tokens`, `info.cost` |
| Gotchas | Prints a warning unless stdin is `/dev/null` | — | Without `--standalone` it collides with the user's background service port. Its default model routed to OpenRouter, which the account's ZDR setting blocks, so pass `-m` explicitly. Real-mode runs add sessions to the user's history |

## Local account state seen (not arena bugs)
- **opencode:** GitHub Copilot is "not licensed", and the Z.ai Coding Plan has no balance. OpenRouter works (`openrouter/anthropic/claude-haiku-4.5`, `openrouter/openai/gpt-5-mini`).
- **codex:** works after the upgrade to 0.164.0.

## Consequences for the design
- **Adapters:** each harness adapter declares its env-isolation recipe, how to seed auth in a clean home, and how to collect metrics. Collecting may need a post-run call; opencode needs `session export`.
- **Preflight:** a clean claude contestant needs `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`. A clean opencode contestant needs an env-keyed provider and an explicit model. Preflight checks these and explains how to fix them before any run starts.
- **Cost is not uniform:** codex reports tokens but no dollar cost, so the scorecard shows cost only where the harness reports it.
